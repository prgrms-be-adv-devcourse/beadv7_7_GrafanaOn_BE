

# (프론트엔드) 행동 데이터 전달 가이드

### API

```http
POST /api/behaviors
Content-Type: application/json
```

### 요청 예시

```json
{
  "eventId": "3ec20d01-5502-4f2a-8b9c-1a2b3c4d5e6f",
  "recommendationId": "rec-abc123",
  "memberId": 1,
  "productId": 1001,
  "eventType": "CLICK",
  "occurredAt": "2026-08-30T20:10:30"
}
```

### 필드

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `eventId` | String | 필수 | 이벤트 고유 식별자 |
| `recommendationId` | String | 조건부 | 추천 관련 이벤트의 추천 ID |
| `memberId` | Long | 필수 | 회원 ID |
| `productId` | Long | 필수 | 상품 ID |
| `eventType` | String | 필수 | 이벤트 타입 |
| `occurredAt` | String | 필수 | 실제 이벤트 발생 시간 |

### 이벤트 전달 기준

| 사용자 행동 | 이벤트 | recommendationId |
| --- | --- | --- |
| 일반 상품 → 상세 진입 | `VIEW` | 선택 |
| 추천 카드 실제 노출 | `IMPRESSION` | 필수 |
| 추천 상품 클릭 | `CLICK` | 필수 |
| 추천 상품 → 상세 진입 | `VIEW` | 전달 가능 |
| 상품 찜 | `SCRAP` | 선택 |
| 장바구니 추가 | `CART_ADD` | 선택 |
| 구매 완료 | `PURCHASE` | 선택 |

프론트엔드에서는 관심도 점수나 가중치를 계산하지 않고 **실제로 발생한 사용자 행동만 서버에 전달**해주시면 좋을것같습니다.!

### 추천 상품 노출
추천 API 응답에 상품이 포함된 것만으로 `IMPRESSION`을 기록하지 않고, 실제 사용자 화면에 노출된 시점을 기준으로 기록하고있습니다.
동일 추천 결과에서 동일 상품에 대한 `IMPRESSION`이 반복 전송되지 않도록 중복 전송 방지가 필요할것같아 이 부분은 추가할예정입니다.

#### 추천 상품 클릭 흐름

```text
추천 카드 노출
    ↓
IMPRESSION
    ↓
추천 상품 클릭
    ↓
CLICK
    ↓
상품 상세 진입
    ↓
VIEW
```
일반 상품 목록에서 상품 상세 페이지로 이동하는 경우에는 추천 성과 측정용 `CLICK`이 아닌 `VIEW`만 기록합니다.

**주의사항**
1. 동일한 사용자 행동을 재전송하는 경우 새로운 `eventId`를 생성하지 않고 기존 이벤트의 `eventId`를 유지합니다.
2. `occurredAt`은 API 요청 시간이 아니라 실제 사용자 행동이 발생한 시간입니다.
3. `IMPRESSION`, `CLICK`에는 추천 API 응답에서 받은 `recommendationId`를 전달하고있습니다.
4. 행동 이벤트 전송이 화면 이동이나 사용자 동작을 차단하지 않도록 비동기 처리를 고려하고자합니다.
